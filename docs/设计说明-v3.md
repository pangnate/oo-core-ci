# ONLYOFFICE X2T Core-only 多平台 GitHub Actions 构建方案

> 版本：v3  
> 日期：2026-09-22  
> 目标平台：Linux amd64、Linux arm64、Windows amd64  
> 构建目标：仅编译 X2T 及其必要静态格式库，不构建 ONLYOFFICE Server / SDKJS / Web Apps / DesktopEditor。  
> 适用场景：Basemetas 自维护 ONLYOFFICE Core fork，需要修改 `OOXML/Binary`、格式转换和 X2T 能力，并持续产出三个目标平台的 `x2t`。

---

# 1. 最终结论

本方案不再依赖 ONLYOFFICE 官方 `make.py` 作为日常 CI 入口。

采用：

```text
core fork
│
├── ONLYOFFICE 原始源码
├── 我们修改过的 X2tSLN.pri
├── ci/build-x2t-linux.sh
├── ci/build-x2t-win64.cmd
├── ci/tests/*
└── .github/workflows/build-x2t.yml
        │
        ├── Ubuntu 24.04 x64
        │     ├── linux_64 原生/官方 sysroot
        │     └── linux_arm64 交叉编译/官方 sysroot
        │
        └── Windows Server 2022 x64
              └── win_64 / MSVC v142
```

日常 GitHub Actions **不下载、不编译**：

```text
CEF
V8
OpenSSL
HarfBuzz
Brotli
HEIF
完整 graphics
完整 PdfFile
完整 doctrenderer
完整 DocumentServer
Server
SDKJS
Web Apps
```

日常构建只做：

```text
CryptoPPLib
CompoundFileLib
DocxFormatLib
PPTXFormatLib
XlsbFormatLib
DocFormatLib
PptFormatLib
XlsFormatLib
VbaFormatLib
TxtXmlFormatLib
RtfFormatLib
OdfFormatLib
BinDocument
X2tConverter
```

最后输出：

```text
x2t-linux-amd64
x2t-linux-arm64
x2t-windows-amd64.exe
```

其中本次“分散对齐”修改：

```text
BinaryWriterD.cpp
BinaryReaderD.cpp
BinReaderWriterDefines.h
```

进入：

```text
libBinDocument.a / BinDocument.lib
        ↓
静态链接
        ↓
x2t
```

因此运行时不需要单独替换 `BinDocument` 动态库。

# 2. 为什么直接维护自己的构建入口

官方 `build_tools/make.py` 面向的是：

```text
DocumentServer
DesktopEditor
DocumentBuilder
SDKJS
Web Apps
完整 Core
```

而不是“只重新链接一个 X2T”。

直接走官方完整流程会引入：

```text
make_common
CEF
V8
完整 Core dynamic libraries
JS build
server build
deploy
```

这与我们的目标不一致。

既然：

```text
Core 源码
构建脚本
CI
SDK
```

全部由我们维护，那么最简单可靠的方式就是：

> 直接使用 Core 本身已经存在的 `X2tSLN.pro`，维护一套专用的 X2T Build SDK 和脚本。

这样甚至可以把 `build_tools` 从日常 X2T CI 中完全移除。

# 4. 必须修改 X2tSLN.pri

当前 `X2tConverter.pri` 会链接：

```text
CryptoPPLib
```

但官方 `X2tSLN.pri` 没有负责构建 `CryptoPPLib`。

完整官方 core build 之所以没问题，是因为 `sln.json` 会提前构建 Crypto++。

如果脱离完整 `sln.json`，必须补上。

修改：

```text
core/X2tConverter/build/Qt/X2tSLN.pri
```

## 4.1 SUBDIRS

从：

```qmake
SUBDIRS = \
    XlsbFormatLib \
    ...
```

改成：

```qmake
SUBDIRS = \
    CryptoPPLib \
    XlsbFormatLib \
    VbaFormatLib \
    DocxFormatLib \

    BinDocument \
    TxtXmlFormatLib \
    RtfFormatLib \
    PptFormatLib \
    DocFormatLib \
    OdfFormatLib \
    XlsFormatLib \
    CompoundFileLib \
    X2tConverter
```

增加：

```qmake
CryptoPPLib.file = ../../../Common/3dParty/cryptopp/project/cryptopp.pro
```

修改：

```qmake
X2tConverter.depends = \
```

# 9. Linux 动态库来源

Linux 有一个优势：

> linker 可以直接使用 `.so`。

所以：

```text
core/build/lib/linux_64/*.so*
core/build/lib/linux_arm64/*.so*
```

可以从与 Core baseline 完全相同的已知可运行 runtime 中提取。

例如：

```text
当前 Basemetas Runtime
或者
对应版本 ONLYOFFICE FileConverter Runtime
```

推荐直接完整保留：

```text
FileConverter/bin 或 core/build/lib 中涉及的全部 *.so*
```

而不是人为只挑 17 个文件。

这样可避免：

```text
libA.so -> libB.so
```

的间接链接依赖遗漏。

# 10. Windows Build SDK

Windows 和 Linux 最大的区别：

> MSVC linker 不能直接拿 DLL 链接，必须有 `.lib` import library。

因此：

```text
从运行时安装目录复制 *.dll
```

**不够。**

Windows SDK 必须保存一次真实编译产生的：

```text
*.lib
+
*.dll
```

建议结构：

```text
sdk-win64/
├── qt/
│   └── 5.15.2/
│       └── msvc2019_64/
│
└── overlay/
    └── core/
        ├── Common/
        │   └── 3dParty/
        │       ├── boost/
        │       │   └── build/
        │       │       └── win_64/
        │       │
        │       └── icu/
        │           └── win_64/
        │               ├── icu/
        │               │   └── include/
        │               └── build/
        │                   ├── icuuc.lib
        │                   ├── icudt.lib
        │                   ├── icuuc74.dll
        │                   └── icudt74.dll
        │
        └── build/
            └── lib/
                └── win_64/
                    ├── graphics.lib
                    ├── graphics.dll
                    ├── kernel.lib
                    ├── kernel.dll
                    ├── ...
                    └── ooxmlsignature.*
```

# 11. Windows Build SDK 的首次来源

Windows 不建议从安装程序中直接提取，因为：

```text
安装包通常只有 DLL
没有 import LIB
```

第一次 Windows Build SDK 必须来自：

```text
一次完整的、同 baseline 的 Windows Core build
```

或者已有的内部 Windows build artifact。

这是一次性 bootstrap。

以后：

```text
X2T 日常构建
```

都只复用该 SDK。

因此 Windows 支持应拆成：

```text
Bootstrap Build SDK（低频）
        ↓
日常 X2T CI（高频）
```

# 14. Windows Qt

Windows 不再依赖 ONLYOFFICE build_tools 提供 Qt。

我们自己固定：

```text
Qt 5.15.2
win64_msvc2019_64
```

原因：

```text
1. Qt 5.15.2 对 VS2019/v142 成熟
2. x2t 本身 QT -= core gui
3. 主要需要的是 qmake/mkspec
4. 比 Qt 5.9.9 更容易在现代 Windows CI 环境保存和维护
```

可用 `aqtinstall` 一次性取得：

```bash

  windows desktop \
  5.15.2 \
  win64_msvc2019_64 \
  -O C:\Qt
```

然后完整镜像：

```text
C:\Qt\5.15.2\msvc2019_64
```

到自己的 Build SDK。

日常 CI 不运行 `aqtinstall`。

# 16. Windows 为什么使用 v142，而不是 v143

ONLYOFFICE 当前公开 pipeline 仍然使用：

```text
Visual Studio 2019
```

并传：

```text
--vs-version 2019
```

`boost.pri` 当前也明确：

```qmake
vs2019:VS_VERSION=142
```

最终寻找：

```text
libboost_*-vc142-...
```

因此第一版 Windows Build SDK 应继续使用：

```text
MSVC v142
```

这样最接近官方已有 ABI。

GitHub `windows-2022` 的 VS2022 可以安装/包含 v142 toolset。

CI 需要显式检查：

```text
VC\Tools\MSVC\14.29.*
```

并使用：

```cmd
vcvarsall.bat x64 -vcvars_ver=14.29
```

这样：

```text
VS IDE = 2022
Compiler Toolset = v142
```

二者并不冲突。

# 19. Ubuntu 16 Sysroot 为什么继续保留

Host：

```text
Ubuntu 24.04
```

Target：

```text
Ubuntu 16 compatible sysroot
```

是两回事。

保留它的原因：

```text
1. 与现有 ONLYOFFICE runtime ABI 基线一致
2. 避免新 x2t 引入更高 GLIBC 需求
3. ARM64 官方 cross compiler 就在这套体系中
4. 只替换 x2t 时风险最低
```

如果未来所有 Linux `.so` 都由我们在新 toolchain 上全量重编，再统一升级 sysroot。

# 20. Linux Build Script

新增：

```text
core/ci/build-x2t-linux.sh
```

建议：

```bash
#!/usr/bin/env bash

set -euo pipefail

TARGET="${1:?target required: linux_64|linux_arm64}"
SDK_ROOT="${X2T_SDK_ROOT:?X2T_SDK_ROOT required}"

CORE_ROOT="$(cd "$(dirname "$0")/.." && pwd)"
PRO_DIR="$CORE_ROOT/X2tConverter/build/Qt"

export PRODUCT_VERSION="${PRODUCT_VERSION:-0.0.0}"
export BUILD_NUMBER="${BUILD_NUMBER:-0}"

case "$TARGET" in
  linux_64)
    QMAKE="$SDK_ROOT/qt/Qt-5.9.9/gcc_64/bin/qmake"
    TARGET_SYSROOT="$SDK_ROOT/sysroot/ubuntu16-amd64-sysroot"
    COMPILER_SYSROOT="$TARGET_SYSROOT"
    PLATFORM_CONFIG=()
    ;;

  linux_arm64)
    QMAKE="$SDK_ROOT/qt/Qt-5.9.9/gcc_arm64/bin/qmake"
    TARGET_SYSROOT="$SDK_ROOT/sysroot/ubuntu16-arm64-sysroot"

    # aarch64-linux-gnu-g++ 位于 amd64 host sysroot
    COMPILER_SYSROOT="$SDK_ROOT/sysroot/ubuntu16-amd64-sysroot"

    PLATFORM_CONFIG=("CONFIG+=linux_arm64")
    ;;

  *)
    echo "Unsupported target: $TARGET"
    exit 2
    ;;
esac

test -x "$QMAKE"
test -d "$TARGET_SYSROOT"
test -d "$COMPILER_SYSROOT"

export QMAKE_CUSTOM_SYSROOT="$TARGET_SYSROOT"
export QMAKE_CUSTOM_SYSROOT_BIN="$COMPILER_SYSROOT/usr/bin"

export PKG_CONFIG_SYSROOT_DIR="$TARGET_SYSROOT"

cd "$PRO_DIR"

rm -f Makefile .qmake.stash

"$QMAKE" \
  -nocache \
  X2tSLN.pro \
  "CONFIG+=core" \
  "CONFIG+=release" \
  "CONFIG+=no_tests" \
  "${PLATFORM_CONFIG[@]}"

make -j"$(nproc)"

X2T="$CORE_ROOT/build/bin/$TARGET/x2t"

test -x "$X2T"

file "$X2T"

echo "Built: $X2T"
```

# 22. Windows Build Script

新增：

```text
core/ci/build-x2t-win64.cmd
```

内容：

```bat
@echo off
setlocal EnableExtensions

if "%X2T_SDK_ROOT%"=="" (
  echo X2T_SDK_ROOT is required
  exit /b 2
)

if "%VS_VCVARSALL%"=="" (
  echo VS_VCVARSALL is required
  exit /b 2
)

if "%PRODUCT_VERSION%"=="" set PRODUCT_VERSION=0.0.0
if "%BUILD_NUMBER%"=="" set BUILD_NUMBER=0

call "%VS_VCVARSALL%" x64 -vcvars_ver=14.29

if errorlevel 1 exit /b 1

set QT_ROOT=%X2T_SDK_ROOT%\qt\5.15.2\msvc2019_64

if not exist "%QT_ROOT%\bin\qmake.exe" (
  echo qmake.exe not found
  exit /b 1
)

set PATH=%QT_ROOT%\bin;%PATH%

cd /d "%~dp0..\X2tConverter\build\Qt"

if exist Makefile del /q Makefile
if exist .qmake.stash del /q .qmake.stash

qmake.exe ^
  -nocache ^
  X2tSLN.pro ^
  "CONFIG+=core" ^
  "CONFIG+=release" ^
  "CONFIG+=no_tests" ^
  "CONFIG+=vs2019"

if errorlevel 1 exit /b 1

set CL=/MP

nmake /NOLOGO

if errorlevel 1 exit /b 1

if not exist "%~dp0..\build\bin\win_64\x2t.exe" (
  echo x2t.exe not found
  exit /b 1
)

echo Built:
echo %~dp0..\build\bin\win_64\x2t.exe

exit /b 0
```

# 26. Baseline 校验

仓库增加：

```text
ci/x2t-sdk-baseline.txt
```

内容：

```text
<CORE_BASELINE_SHA>
```

CI 解压 SDK 后读取：

```text
manifest.coreBaseline
```

不一致则：

```text
fail
```

不能继续编译。

注意这里的 baseline：

```text
不是当前 feature commit
```

而是：

```text
当前 fork 所基于的上游 Core 基线
```

例如：

```text
upstream-core 9.1.x commit
```

允许：

```text
baseline + 我们自己的 BinaryWriterD 修改
```

但不允许：

```text
SDK 来自 9.0
源码已经 rebased 到 9.2
```

## 27.1 Linux Job

```yaml
name: Build X2T

on:
  workflow_dispatch:

  push:
    branches:
      - main
      - "release/**"
    paths:
      - "Common/**"
      - "OOXML/**"
      - "MsBinaryFile/**"
      - "OdfFile/**"
      - "RtfFile/**"
      - "TxtFile/**"
      - "X2tConverter/**"
      - "ci/**"

permissions:
  contents: read

jobs:
  linux:
    runs-on: ubuntu-24.04
    timeout-minutes: 120

    steps:
      - uses: actions/checkout@v4
        with:
          path: core
          fetch-depth: 1

      - name: Install host dependencies
        run: |
          sudo apt-get update

          sudo DEBIAN_FRONTEND=noninteractive apt-get install -y \
            build-essential \
            ca-certificates \
            curl \
            git \
            python3 \
            perl \
            pkg-config \
            file \
            binutils \
            rsync \
            zstd \
            xz-utils

      - name: Download Linux Build SDK
        env:
          SDK_URL: ${{ vars.X2T_LINUX_SDK_URL }}
          SDK_SHA256: ${{ vars.X2T_LINUX_SDK_SHA256 }}
        run: |
          curl \
            --fail \
            --location \
            --retry 5 \
            --retry-all-errors \
            --connect-timeout 20 \
            -o sdk.tar.zst \
            "$SDK_URL"

          echo "$SDK_SHA256  sdk.tar.zst" \
            | sha256sum -c -

          tar --zstd -xf sdk.tar.zst

          rsync -a \
            sdk-linux/overlay/ \
            "$GITHUB_WORKSPACE/"

      - name: Validate Linux SDK
        run: |
          test -x sdk-linux/qt/Qt-5.9.9/gcc_64/bin/qmake
          test -x sdk-linux/qt/Qt-5.9.9/gcc_arm64/bin/qmake

          test -d sdk-linux/sysroot/ubuntu16-amd64-sysroot
          test -d sdk-linux/sysroot/ubuntu16-arm64-sysroot

          test -d core/Common/3dParty/boost/build/linux_64
          test -d core/Common/3dParty/boost/build/linux_arm64

          test -d core/Common/3dParty/icu/linux_64/build
          test -d core/Common/3dParty/icu/linux_arm64/build

          test -d core/build/lib/linux_64
          test -d core/build/lib/linux_arm64

      - name: Build Linux amd64
        env:
          X2T_SDK_ROOT: ${{ github.workspace }}/sdk-linux
        run: |
          chmod +x core/ci/build-x2t-linux.sh
          core/ci/build-x2t-linux.sh linux_64

      - name: Build Linux arm64
        env:
          X2T_SDK_ROOT: ${{ github.workspace }}/sdk-linux
        run: |
          core/ci/build-x2t-linux.sh linux_arm64

      - name: Verify
        run: |
          file core/build/bin/linux_64/x2t
          file core/build/bin/linux_arm64/x2t

          readelf -h core/build/bin/linux_64/x2t
          readelf -h core/build/bin/linux_arm64/x2t

          file core/build/bin/linux_64/x2t \
            | grep -Ei 'x86-64|x86_64'

          file core/build/bin/linux_arm64/x2t \
            | grep -Ei 'aarch64|ARM'

      - name: Package
        run: |
          mkdir -p dist

          cp \
            core/build/bin/linux_64/x2t \
            dist/x2t-linux-amd64

          cp \
            core/build/bin/linux_arm64/x2t \
            dist/x2t-linux-arm64

          sha256sum dist/* > dist/SHA256SUMS

      - uses: actions/upload-artifact@v4
        with:
          name: x2t-linux-${{ github.sha }}
          path: dist/
```

## 27.2 Windows Job

追加：

```yaml
  windows:
    runs-on: windows-2022
    timeout-minutes: 120

    steps:
      - uses: actions/checkout@v4
        with:
          path: core
          fetch-depth: 1

      - name: Download Windows Build SDK
        shell: powershell
        env:
          SDK_URL: ${{ vars.X2T_WIN64_SDK_URL }}
          SDK_SHA256: ${{ vars.X2T_WIN64_SDK_SHA256 }}
        run: |
          curl.exe `
            --fail `
            --location `
            --retry 5 `
            --retry-all-errors `
            -o sdk-win64.7z `
            "$env:SDK_URL"

          $hash = (
            Get-FileHash sdk-win64.7z -Algorithm SHA256
          ).Hash.ToLower()

          if ($hash -ne $env:SDK_SHA256.ToLower()) {
            throw "SDK checksum mismatch"
          }

          7z x sdk-win64.7z -y

          Copy-Item `
            sdk-win64\overlay\* `
            . `
            -Recurse `
            -Force

      - name: Locate Visual Studio
        shell: powershell
        run: |
          $vswhere = `
            "${env:ProgramFiles(x86)}\Microsoft Visual Studio\Installer\vswhere.exe"

          $vs = & $vswhere `
            -latest `
            -products * `
            -requires Microsoft.VisualStudio.Component.VC.Tools.x86.x64 `
            -property installationPath

          if (-not $vs) {
            throw "Visual Studio not found"
          }

          $vcvars = `
            Join-Path $vs "VC\Auxiliary\Build\vcvarsall.bat"

          if (-not (Test-Path $vcvars)) {
            throw "vcvarsall.bat not found"
          }

          $v142 = Get-ChildItem `
            (Join-Path $vs "VC\Tools\MSVC") `
            -Directory |
            Where-Object {
              $_.Name -like "14.29*"
            } |
            Select-Object -First 1

          if (-not $v142) {
            throw "MSVC v142 toolset not found"
          }

          "VS_VCVARSALL=$vcvars" |
            Out-File `
              -FilePath $env:GITHUB_ENV `
              -Encoding utf8 `
              -Append

      - name: Build Windows amd64
        shell: cmd
        env:
          X2T_SDK_ROOT: ${{ github.workspace }}\sdk-win64
        run: |
          call core\ci\build-x2t-win64.cmd

      - name: Prepare runtime DLLs
        shell: powershell
        run: |
          Copy-Item `
            core\build\lib\win_64\*.dll `
            core\build\bin\win_64\ `
            -Force

          Copy-Item `
            core\Common\3dParty\icu\win_64\build\*.dll `
            core\build\bin\win_64\ `
            -Force

      - name: Verify Windows binary
        shell: cmd
        run: |
          call "%VS_VCVARSALL%" x64 -vcvars_ver=14.29

          dumpbin /headers ^
            core\build\bin\win_64\x2t.exe ^
            | findstr /i "machine"

          if errorlevel 1 exit /b 1

      - name: Package Windows
        shell: powershell
        run: |
          New-Item dist -ItemType Directory -Force

          Copy-Item `
            core\build\bin\win_64\x2t.exe `
            dist\x2t-windows-amd64.exe

          $hash = (
            Get-FileHash `
              dist\x2t-windows-amd64.exe `
              -Algorithm SHA256
          ).Hash.ToLower()

          "$hash  x2t-windows-amd64.exe" |
            Set-Content dist\SHA256SUMS

      - uses: actions/upload-artifact@v4
        with:
          name: x2t-windows-${{ github.sha }}
          path: dist/
```

# 34. 不建议把 SDK 放 actions/cache

Build SDK 属于：

```text
版本化构建输入
```

不是临时 cache。

因此最好：

```text
对象存储 + SHA256
```

而不是：

```text
actions/cache
```

原因：

```text
可审计
可重现
不会自动淘汰
版本绑定明确
```

# 35. Windows 的真实限制

Linux Build SDK 可以从 runtime 提取 `.so` 后用于链接。

Windows 不行。

Windows 必须具有：

```text
*.lib import libraries
```

因此第一次引入 Windows 支持时，确实需要：

> **做一次完整 Windows Core dependency bootstrap。**

这不是日常 CI 的成本。

完成第一次 SDK 后，后续 X2T 编译不再需要完整 Core build。

---

# 36. 为什么 Windows 方案仍然值得做

完成 Windows SDK 后：

```text
修改 BinaryWriterD.cpp
        ↓
GitHub Windows Job
        ↓
重新编静态格式库
        ↓
重新链接 x2t.exe
```

整个过程不再需要：

```text
CEF
V8
DesktopEditor
Server
Web Apps
```

因此后续维护成本仍然很低。

这版方案比使用官方完整 `build_tools` 更适合 Basemetas 当前架构。

```text
不需要官方 server
不需要 CEF
不需要 V8
不需要 Node
不需要 Java
```

真正需要长期维护的是：


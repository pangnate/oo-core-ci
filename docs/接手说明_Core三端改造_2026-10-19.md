## 最近一次失败与本次修复

上一轮 Actions #10（run `39254838375`，提交 `550f0d77`）运行约 58 分钟，V8 monolith 已到 `[1700/1700]`，随后 SDK probe 编译失败：

```text
fatal error C1083: Cannot open include file: 'libplatform/libplatform-export.h': No such file or directory
```

原因是 probe 只有 V8 根目录 include path，缺少 V8 SDK 的 `include` 子目录。本次提交已在 probe 编译参数中同时传入 `/I<v8-root>` 与 `/I<v8-root>/include`，并加了回归测试。run #10 失败，不可作为 promote 来源。

更早的失败曾先后暴露 depot_tools bootstrap/Python、嵌套 Git 长路径、Windows 工具定位等问题；这些修复已进入 main。具体历史与证据见 `docs/测试/luna/LUNA-CORE-BLD-V8-01/evidence.md`。

## 本卡实现范围与约束

`3521e1c1` 已推送到 `origin/main`，包含固定 SDK 恢复 action、手动 workflow、Windows V8 构建/探针脚本、归档管理脚本、复用/锁测试、README/任务状态和清理被跟踪的 Python bytecode。该提交不修改 Core 官方源码或功能 patch。当前规则仍是：**Core 功能改动只放在 `patches/core/*.patch`，禁止把已打功能补丁的 `core/`快照作为交付。**

SDK卡锁定 V8 8.9、depot_tools、Core/build_tools来源及 MSVC v142 14.29 x64 动态 CRT ABI。V8 bootstrap 是独立手动任务；普通 Core 功能构建不得隐式重编 V8。`reuse` 应只恢复固定 SDK并运行 probe；`build` 仅在固定 SDK缺失时冷构建；`promote` 仅导入成功 run 的同锁制品，不能用于失败 run，也不会为发布重编。

用户本地是 Windows 开发环境，但本任务的 C++ 构建和原生 probe 均在 GitHub Actions 执行。本机只做脚本、锁、单元测试、工作流静态检查和补丁合同验证。

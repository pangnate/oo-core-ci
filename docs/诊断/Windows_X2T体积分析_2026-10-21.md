## 已确认的主要来源

`core/MsBinaryFile/XlsFile/Format/Logic/GlobalWorkbookInfo.h` 将 64 个颜色定义为 `static const std::wstring DefaultPalette[]`。每个包含它的编译单元拥有独立数组及动态构造、析构、异常清理代码。

新 map 记录 2,039 个不同地址的 `??__EDefaultPalette@XLS@@YAXXZ`，以及 2,039 个数组实例。用 PE `.pdata` 函数边界核对，2,039 个构造函数长度均为 3,453 bytes，合计 7,040,667 bytes。这不是 map 相邻符号估计。

旧 EXE 无 map，因此扫描 x64 RIP 相对字符串引用并匹配完整调色板特征：同一函数引用前五个特征颜色，函数长度为 3,453 bytes。旧样本找到 63 个，新样本找到 2,039 个；新样本与 map 的初始化函数地址对应。两边另有一个 429-byte 的颜色处理函数，已排除，不能把它计作初始化实例。

新 map 中调色板符号的独占相邻地址区间为：代码 9,167,344 bytes、只读元数据 701,544 bytes、数组数据 4,175,872 bytes。代码和只读元数据包含对齐，采用相邻符号区间只能估算；数组数据则正好等于 2,039 × 64 × 32 bytes。按旧 63 份与新 2,039 份的差异折算，调色板重复可估计解释约 13,610,812 bytes，约占总增量 79%，不是精确链接前后差额。

新 EXE 还存在同类重复：`mapEncodingsICU` 初始化 2,153 份，`c_oContentTypeFileName` 501 份，多种 XML 字符串各 480 份。它们和其他代码生成差异仍需与优化后的新 map 比较，不能把剩余约 3.68 MB 全部归于某一对象。

## 编译方式与排除项

- 当前真实编译日志按独立 `.cpp` 生成对象；qmake 未启用 `build_monolith_objects`。上游 Docx/Xls/Odf/Rtf 等项目提供该合并分支。旧二进制较少的初始化副本和 Rich 编译单元记录与合并编译相符，但没有旧构建命令，不能宣布旧构建参数已完全复原。
- 当前链接确实使用 `/OPT:REF /OPT:ICF /INCREMENTAL:NO`；动态初始化和有独立地址的静态数据阻止这些实例直接折叠，不能将增大归咎于未开启 Release 链接优化。
- 新旧 linker 均为 14.29，导出函数均 13 个；依赖 DLL 名单相同，PdfFile 导入方法数增加 2。没有把整套 DLL 静态合入 EXE 的证据。
- `.rsrc` 大小未变；版本品牌资源不是 17 MB 增量来源。新 EXE 没有 PE 外的大型尾部数据，也没有附加 PDB 内容。

## 修改与验证

新增 `019-xls-share-default-palette.patch`：头文件保留 `extern const std::wstring DefaultPalette[64]`，64 个原值完整移入已有 `GlobalWorkbookInfo.cpp` 的单一定义。实际唯一使用方是 `Biff_records/Font.cpp` 的运行期 `.substr(2)`，调用不变。不通过全量合并编译来换取体积，以免扩大单个编译进程的内存需求。

- 新补丁在真实 Core 文件上应用通过，85 项测试通过；加入 map 计数回归后共 86 项通过。
- 多编译单元原生小程序确认数组地址相同、64 个颜色与截取结果一致，`nm` 仅有一个数组定义。
- 使用锁定 Boost 1.72 头，真实修改后的 `GlobalWorkbookInfo.cpp` 在 WSL g++ C++11 语法检查通过。不是 Windows 完整编译证明。
- 补丁暂存检查通过，更新 21,118 文件的 staging 指纹及补丁清单哈希；官方 pristine Core 未改。
- Windows 体积报告新增动态初始化实例计数；流水线要求调色板实例最多 1 个，避免再次无提示生成上千份。

最终节省字节数、Windows 链接成功和转换回归必须等待携带 019 补丁的构建。当前 13.6 MB 是旧/新 map 与反汇编分析的估计，不能宣称已实测缩回旧体积。
